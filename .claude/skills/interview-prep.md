# Interview Preparation - PM IT สสส.

## STAR Method

> **S**ituation → **T**ask → **A**ction → **R**esult

---

## 1. แนะนำตัว (2-3 นาที)

```
สวัสดีครับ/ค่ะ ผม/ดิฉัน [ชื่อ-นามสกุล]

ปัจจุบันทำงานตำแหน่ง [ตำแหน่ง] ที่ [บริษัท] มา [X] ปี
รับผิดชอบ: [งานหลักที่เกี่ยวข้องกับ PM]

ประสบการณ์ที่เกี่ยวข้อง:
• บริหารโครงการ IT มูลค่า [X] ล้านบาท จำนวน [X] โครงการ
• ทีมงานที่ดูแล [X] คน (Developer, QA, BA, Designer)
• Methodologies: Agile/Scrum, Waterfall, Hybrid

ผมสนใจตำแหน่งนี้เพราะ:
1. ต้องการนำความรู้มาพัฒนาระบบที่มีผลกระทบต่อสังคม
2. สสส. เป็นองค์กรที่มีพันธกิจชัดเจนด้านสุขภาวะ
3. ท้าทายในการบริหารโครงการภาครัฐที่มีความซับซ้อน
```

## 2. คำถามที่มักถูกถาม

### Q1: โครงการที่ภูมิใจที่สุด?

**แนวตอบ (STAR):**
- **S:** โครงการพัฒนาระบบ [ชื่อระบบ] งบประมาณ X ล้าน ระยะเวลา X เดือน
- **T:** เป้าหมายคือ [ระบุเป้าหมาย] โดยมีข้อจำกัดด้าน [เวลา/งบ/คน]
- **A:** ใช้วิธี [Agile/Waterfall] แบ่ง Sprint, Daily Standup, จัดการ Risk, Communicate กับ Stakeholder
- **R:** ส่งมอบตรงเวลา, User Satisfaction 90%+, ลด Cost X%

---

### Q2: เคยเจอปัญหาอะไร แก้ยังไง?

| ปัญหา | วิธีแก้ |
|-------|--------|
| **Scope Creep** | Change Request Process, MoSCoW Prioritization |
| **ทีมลาออกกลางโครงการ** | Knowledge Transfer Plan, Cross-training |
| **Requirement ไม่ชัด** | Workshop, Prototype/Wireframe, Sign-off ทุก Phase |
| **โครงการ Delay** | Re-prioritize, เพิ่ม Resource, Fast-track, Communicate โปร่งใส |

---

### Q3: รู้จัก สสส. มากน้อยแค่ไหน?

**ต้องรู้:**
- สสส. = สำนักงานกองทุนสนับสนุนการสร้างเสริมสุขภาพ
- พันธกิจ: สนับสนุนการสร้างเสริมสุขภาพ ลดปัจจัยเสี่ยง
- งบประมาณ: มาจากภาษีเหล้า/บุหรี่ 2%
- กระบวนการ: พัฒนาข้อเสนอ → อนุมัติ → เบิกเงิน → ส่งงาน → ปิดโครงการ

**ระบบ IT ที่เกี่ยวข้อง:**
- ระบบบริหารโครงการ (Grant Management)
- ระบบติดตามและประเมินผล
- เชื่อมต่อ: e-GP, GFMIS, e-Budget

---

### Q4: ถ้าได้รับตำแหน่ง จะทำอะไรใน 90 วันแรก?

| ช่วง | กิจกรรม |
|------|---------|
| **30 วันแรก (Learn)** | เรียนรู้ระบบ IT, Pain Points, ทำความรู้จักทีม, Review โครงการปัจจุบัน |
| **30-60 วัน (Contribute)** | เสนอ Quick Wins, จัดทำ Dashboard, ปรับปรุง Process |
| **60-90 วัน (Lead)** | เสนอ Roadmap, เริ่มโครงการ Improvement, สร้าง KPI |

---

### Q5: จุดแข็ง-จุดอ่อน?

**จุดแข็ง (เลือก 2-3 ข้อ):**
- Communication: สื่อสารกับ Technical และ Non-technical ได้ดี
- Problem Solving: วิเคราะห์ปัญหาเป็นระบบ, หา Root Cause
- Stakeholder Management: บริหาร Expectation, สร้างความร่วมมือ

**จุดอ่อน (ต้องมี + แสดงการพัฒนา):**
- "บางครั้ง Perfectionist → ตอนนี้ใช้ 80/20 Rule"
- "เคยไม่ถนัด Delegate → ตอนนี้ฝึก Trust ทีมมากขึ้น"
- "Domain ภาครัฐยังไม่ลึก → กำลังศึกษา พ.ร.บ. จัดซื้อจัดจ้าง"

## 3. คำถามเชิงเทคนิค

### Agile vs Waterfall ใช้เมื่อไหร่?
- **Waterfall:** Requirement ชัด, Fixed Scope/Budget, ภาครัฐ (TOR ชัด)
- **Agile:** Requirement ไม่ชัด, ต้องการ Feedback เร็ว, Innovation
- **Hybrid:** Waterfall กำกับ Milestone + Agile ใน Development

### Risk Management ทำยังไง?
1. **Identify** → Brainstorm, Lessons Learned
2. **Analyze** → Probability x Impact
3. **Plan** → Mitigate, Transfer, Accept, Avoid
4. **Monitor** → Review ทุกสัปดาห์

### Stakeholder Management?
1. **Identify** → ใครบ้างที่เกี่ยวข้อง
2. **Analyze** → Power/Interest Matrix
3. **Plan** → Communication Plan
4. **Engage** → ประชุม, Report, สร้าง Buy-in

- มี KPI หลักอะไรบ้างสำหรับตำแหน่งนี้?
