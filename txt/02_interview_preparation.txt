┌─────────────────────────────────────────────────────────────────────────────┐
│ Q1: "โครงการที่ภูมิใจที่สุด?"                                               │
├─────────────────────────────────────────────────────────────────────────────┤
│ แนวตอบ (STAR):                                                             │
│ S: "โครงการพัฒนาระบบ [ชื่อระบบ] งบประมาณ X ล้าน ระยะเวลา X เดือน"          │
│ T: "เป้าหมายคือ [ระบุเป้าหมาย] โดยมีข้อจำกัดด้าน [เวลา/งบ/คน]"             │
│ A: "ผมใช้วิธี [Agile/Waterfall] แบ่ง Sprint, ประชุม Daily Standup,         │
│     จัดการ Risk ด้วย [วิธีการ], Communicate กับ Stakeholder ทุกสัปดาห์"     │
│ R: "ส่งมอบตรงเวลา/ก่อนกำหนด, User Satisfaction 90%+, ลด Cost X%"           │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ Q2: "เคยเจอปัญหาอะไรในการบริหารโครงการ แก้ยังไง?"                           │
├─────────────────────────────────────────────────────────────────────────────┤
│ ตัวอย่างปัญหา + วิธีแก้:                                                    │
│                                                                             │
│ 1. Scope Creep (งานบานปลาย)                                                │
│    → ใช้ Change Request Process, ประเมิน Impact ก่อนรับงานเพิ่ม            │
│    → จัดลำดับความสำคัญด้วย MoSCoW (Must/Should/Could/Won't)                │
│                                                                             │
│ 2. ทีมงานลาออกกลางโครงการ                                                   │
│    → Knowledge Transfer Plan, Documentation ที่ดี                          │
│    → Cross-training ให้ทีมทำงานแทนกันได้                                   │
│                                                                             │
│ 3. Requirement ไม่ชัด/เปลี่ยนบ่อย                                           │
│    → Workshop กับ User, Prototype/Wireframe ก่อน Dev                       │
│    → Sign-off ทุก Phase, ใช้ Agile เพื่อ Feedback เร็ว                     │
│                                                                             │
│ 4. โครงการ Delay                                                           │
│    → Re-prioritize scope, เพิ่ม Resource, Fast-track activities           │
│    → Communicate กับ Stakeholder อย่างโปร่งใส                              │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ Q3: "รู้จัก สสส. มากน้อยแค่ไหน?"                                            │
├─────────────────────────────────────────────────────────────────────────────┤
│ ต้องรู้:                                                                    │
│ • สสส. = สำนักงานกองทุนสนับสนุนการสร้างเสริมสุขภาพ                          │
│ • พันธกิจ: สนับสนุนการสร้างเสริมสุขภาพ ลดปัจจัยเสี่ยง                       │
│ • งบประมาณ: มาจากภาษีเหล้า/บุหรี่ 2%                                        │
│ • โครงสร้าง: มีแผนงานต่างๆ เช่น แผนควบคุมยาสูบ, แผนแอลกอฮอล์               │
│ • กระบวนการหลัก: พัฒนาข้อเสนอ → อนุมัติ → เบิกเงิน → ส่งงาน → ปิดโครงการ   │
│                                                                             │
│ ระบบ IT ที่เกี่ยวข้อง:                                                      │
│ • ระบบบริหารโครงการ (Grant Management)                                     │
│ • ระบบติดตามและประเมินผล                                                    │
│ • ระบบการเงินและงบประมาณ                                                    │
│ • ต้องเชื่อมต่อระบบราชการ: e-GP, GFMIS, e-Budget                           │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐

│ • เสนอ Roadmap การพัฒนาระบบ IT                                             │
│ • เริ่มโครงการ Improvement ที่ได้รับอนุมัติ                                 │

Q: "Agile vs Waterfall ใช้เมื่อไหร่?"
─────────────────────────────────────
Waterfall: Requirement ชัด, Fixed Scope/Budget, ภาครัฐ (ต้อง TOR ชัด)
Agile:     Requirement ไม่ชัด, ต้องการ Feedback เร็ว, Innovation Project
Hybrid:    ใช้ Waterfall กำกับ Milestone + Agile ใน Development Phase

Q: "Risk Management ทำยังไง?"
─────────────────────────────────────
1. Identify  → Brainstorm กับทีม, ดูจาก Lessons Learned
2. Analyze   → ประเมิน Probability x Impact (High/Medium/Low)
3. Plan      → Mitigate (ลด), Transfer (โอน), Accept (รับ), Avoid (หลีก)
4. Monitor   → Review ทุกสัปดาห์ใน Status Meeting

Q: "Stakeholder Management?"
─────────────────────────────────────
1. Identify   → ใครบ้างที่เกี่ยวข้อง (Sponsor, User, Vendor, IT)
2. Analyze    → Power/Interest Matrix (Manage Closely/Keep Satisfied/...)
3. Plan       → Communication Plan (ใคร/อะไร/เมื่อไหร่/Channel)
4. Engage     → ประชุม, Report, สร้าง Buy-in
